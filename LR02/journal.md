### Ожидания по находкам

Исходя из сценария и профиля, ожидаю следующее.

**Правила, которые, скорее всего, сработают:**

- **R8** (не указан источник или дата) — предупреждение. В каждом варианте есть «фоновая» проблема; ожидаю минимум одну находку.
- **R10** (не указан правообладатель) — предупреждение. Аналогично, из фонового шума.
- **R9** (дубликат по sha256) — предупреждение. Возможно, тоже из фонового шума.

**Правила, которые, скорее всего, НЕ сработают:**

- **R5** (ShareAlike при производных и неприемлемом SA) — **не сработает**, потому что в сценарии `catalog` производные **не создаются** (`derivatives: False`). Хотя профиль у меня `sa`, условие правила R5 требует `derivatives == True`.
- **R3** (NonCommercial при коммерческом использовании) — **не сработает**, потому что сценарий некоммерческий.
- **R4** (NoDerivatives при производных) — **не сработает**, потому что производные не создаются.
- **R6** (персональные данные без согласия) — **не сработает**, потому что профиль `sa`, а не `privacy`.
- **R1, R2** (лицензия не указана / не из SPDX) — **не сработают**, потому что профиль `sa`, а не `license`.

**Ожидаемый итог:** ошибок, скорее всего, **НЕ будет**; будут только предупреждения (R8, R10, возможно R9).

### Ожидаемые решения по находкам

- Если найдётся **пропущенная дата получения** (R8) — запросить у поставщика, до ответа пометить в паспорте как «неизвестно», не догадываться.
- Если найдётся **отсутствующий правообладатель** (R10) — запросить данные у источника, до получения не использовать объект в публикации каталога.
- Если найдётся **дубликат** (R9) — исключить дублирующий объект из набора или объединить записи.

### Критерий успеха

- Ожидания записаны **до** запуска.
- Каждая находка имеет решение и обоснование.
- В реестре есть группы **Data Privacy** и **Intellectual Property** (обязательные для варианта 26).
- Вывод отделяет инженерное решение от юридического вопроса.

## Этап 4. Решения по находкам

**Находка 1 (R8, item02):**

**Решение:** запросить у поставщика дату получения. До ответа пометить в паспорте набора как «неизвестно» (не догадываться). Объект не исключать.

**Обоснование:** R8 — предупреждение, не ошибка. Объект item02 (Apache-2.0) не нарушает лицензионных условий для сценария `catalog`. Проблема только в прослеживаемости происхождения. Дата влияет на полноту паспорта, но не блокирует использование.

**Граница инженерного и юридического:** решение «запросить дату» — инженерное (куратор данных может сделать это сам). Решение «использовать объект без точной даты» — организационное: если дату не удастся получить, куратор решает, оставить ли объект с пометкой «дата неизвестна» или исключить его из набора. Юридического конфликта нет.
