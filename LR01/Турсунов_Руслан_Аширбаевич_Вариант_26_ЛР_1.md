**Гипотеза (записана до запуска).** Добавление октавы вводит дополнительный, более мелкий масштаб детали. Ожидается:

**Критерий существенности (задан до эксперимента).** Эффект считается существенным, если |Δ| > 2·s_base, где Δ = mean_pert − mean_base, s_base — выборочное стандартное отклонение метрики по n = 5 базовым запускам. Критерий учебный, не является статистическим тестом.

**Критерии успеха.** Протокол воспроизводимости выполнен (EQ_1_2 = true, EQ_1_4 = true, EQ_1_3 = false, EQ_2_4 = true); паспорт полон; вывод о факторе следует из данных и критерия; ограничения названы.

## 6. Анализ результатов

### 6.1. Интерпретация метрик

Три из четырёх метрик значимо изменились, и все — в сторону **снижения**:

- **contrast** упал на 0.0242 (|Δ|/s = 32.79);
- **edge** упал на 0.0157 (|Δ|/s = 11.13);
- **entropy** упала на 0.2087 бит (|Δ|/s = 41.00);
- **mean** не изменилось (|Δ|/s = 0.13).

Среднее сохранилось — нормировка работает корректно, диапазон яркости после квантования не нарушен. Это прямая проверка специфики варианта 26 (см. журнал, Этап 1).

### 6.2. Почему направление эффекта оказалось обратным гипотезе

Гипотеза предсказывала **рост** энтропии и edge. Фактически они **упали**. Это не ошибка эксперимента, а следствие механизма генератора.

В `lab01_generator.py` на каждой октаве шаг решётки делится на 2:

```python
field = _octave(size, max(1, int(p["cell"]) >> o), rng, p["interp"])
```

При `cell = 2`:
- октава 0: `cell = 2`;
- октава 1: `cell = 1`;
- октава 2 (новая): `max(1, 2 >> 2) = max(1, 0) = 1` — **упор в минимум**.

Третья октава добавляет слой **пиксельного шума** с амплитудой `0.7² = 0.49`. После нормировки (`v = acc / total`) этот шум размывает вклад базовой структуры:

- гистограмма яркости сглаживается → энтропия падает;
- типичная разность соседних пикселей уменьшается после квантования и нормировки → edge падает;
- разброс яркости сжимается → contrast падает;
- средний уровень сохраняется → mean не меняется.

### 6.3. Равномерность зерна

Дополнительный критерий варианта 26 — обсудить равномерность зерна по разбросу s между seed.

| Метрика | s_base | s_pert |
|---|---:|---:|
| mean | 0.0038 | 0.0031 |
| contrast | 0.0007 | 0.0008 |
| edge | 0.0014 | 0.0009 |
| entropy | 0.0051 | 0.0075 |

s очень мало для всех метрик и в базе, и при факторе — это признак **равномерного зерна по кадру**: разные seed дают почти одинаковые метрики. При добавлении октавы равномерность сохраняется. Ожидание из журнала («s может вырасти») подтвердилось лишь частично: s_pert для энтропии вырос (0.0051 → 0.0075), для edge — упал, для остальных — почти не изменился.

### 6.4. Сравнение с гипотезой

| Метрика | Гипотеза | Факт | Совпадение |
|---|---|---|---|
| mean | не изменится | не значимо (|Δ|/s = 0.13) | ✅ подтверждено |
| contrast | может слегка измениться | значимо упал (|Δ|/s = 32.79) | ⚠️ направление не предсказано |
| edge | вырастет | значимо упал (|Δ|/s = 11.13) | ❌ опровергнуто |
| entropy | вырастет | значимо упала (|Δ|/s = 41.00) | ❌ опровергнуто |

**Вывод.** Гипотеза **опровергнута по направлению эффекта**, но **сам факт влияния фактора подтверждён**: |Δ|/s достигает 41, что многократно превышает порог 2. Это показывает, что учебный критерий 2·s фиксирует **наличие** эффекта, но не его **направление**; направление определяется механизмом генератора и требует отдельного анализа.

## 7. Анализ ошибок, угроз валидности и ограничений

### 7.1. Ошибки и их диагностика

**Ошибка 1: запуск без `--seed`.** Два запуска без seed дали разные отпечатки (`1472e7b346e76066` и `ebbcc48c51659a8a`) и предупреждение. Диагностика: прочитать предупреждение, сравнить отпечатки полных массивов, найти в коде источник случайности (при отсутствии `--seed` значение берётся из системного времени). Исправление: всегда передавать `--seed`, записывать его в паспорт, использовать локальный `random.Random(seed)`.

**Ошибка 2 (не ошибка, а находка): расхождение гипотезы с фактом по направлению.** Гипотеза предсказывала рост, факт — падение. Это не ошибка эксперимента, а содержательный результат: он объясняется упором `cell` в минимум на третьей октаве. В отчёте это фиксируется как находка, а не как провал.

### 7.2. Угрозы валидности

- **n = 5** — малая серия. Оценка s сама неточна. Однако в нашем случае эффект **обнаружен** с большим запасом (|Δ|/s до 41), поэтому основному выводу это не угрожает. Для проверки слабых эффектов потребовалось бы больше seed.
- **Одна текстура, один базовый seed.** Результаты не переносятся автоматически на другие контексты (облачное небо, мрамор, водная рябь). Для проверки общности нужны серии по другим контекстам.
- **Учебный критерий 2·s — не статистический тест.** Он не даёт p-value, не учитывает распределение, не различает направление. Это упрощённое правило, заданное заранее.
- **Метрики яркости ≠ эстетика.** Среднее, контраст, edge, энтропия не измеряют «красоту» текстуры и не предсказывают её восприятие.
- **Детерминизм ограничен средой.** Воспроизводимость достигнута в пределах одной среды (CPU, один поток, фиксированный seed). При переносе на GPU, обновлении интерпретатора или параллельном выполнении результат может измениться. Для реальных генеративных моделей (ЛР 5–6) полная побитовая воспроизводимость недостижима из-за недетерминизма CUDA-операций и различий порядка вычислений с плавающей точкой.

### 7.3. Ограничения

- Модель-заменитель, а не реальная генеративная модель.
- Одна среда (Windows 11 + CPython 3.13.1).
- Отсутствие проверки на других ОС и версиях Python.
- Отсутствие статистического теста (использован учебный критерий).

### 10.5. Работа с переменными

- Панель **«Переменные»** → вкладка **«Рабочая область»**. Таблица содержит **шесть** столбцов: «Имя», «Значение», «Класс», «Память», «Размер», «Константа». В МУ упомянуты только три.
- Переменная `seed = 101` отображается как `Int64`. Столбец «Память» пуст (скаляр), «Размер» показывает `()` (пустой кортеж — скаляр не коллекция).
- Кнопка **«Очистить все переменные»** — иконка метлы 🧹, без текстовой подписи. Результат: таблица пуста, ядро работает.
- Кнопка **«Перезапуск ядра»** — иконка мишени 🎯, без текстовой подписи. Результат: ядро перезапускается, все переменные теряются, среда возвращается в исходное состояние.

**Вывод.** Состояние среды (набор переменных) зависит от порядка выполнения ячеек. «Очистить все переменные» удаляет только переменные; «Перезапуск ядра» сбрасывает всё состояние ядра. Оба действия влияют на воспроизводимость. **Поэтому в паспорт записывается порядок запуска.** В отличие от Части А (где источник случайности — seed), в Engee дополнительный источник вариативности — порядок ячеек и состояние ядра Julia.
