### 6.1. Классификация по допуску

| Метрика | Δ | Допуск | Классификация |
|---|---:|---|---|

**Расхождение 2s и допуска отсутствует** — оба критерия согласны для всех метрик.

### 6.2. Статистическая и практическая значимость

**PSNR:**
- **Статистически:** |Δ|/s = **4.98 > 2** — эффект **значим**.
- **Практически:** Δ = **+1.536 дБ > 1.0** — **улучшение**.

Оба критерия согласны: рост d с 8 до 32 **окупается**.

**Разрыв train − test:**
- **Статистически:** |Δ|/s = 0.85 — **незначимо**.
- **Практически:** +0.010 < 0.1 — **в допуске**.

Переобучения **нет**: прирост PSNR не за счёт запоминания.

**Время:**
- **Статистически:** |Δ|/s = 0.62 — **незначимо**.
- **Практически:** −3.5 % — **в допуске**.

Разница во времени — **шум** GPU, не реальный эффект.

### 6.3. Чувствительность вывода к допуску

**PSNR Δ = +1.536 дБ** — **на грани** допуска ±1.0. Если бы допуск был **±1.5 дБ**, эффект стал бы «нейтральным». Это **важная оговорка**: вывод «улучшение» **устойчив**, но при более строгом допуске можно было бы говорить «практически незначимо, хотя статистически заметно».

**Рекомендация для практики:** для этого набора **d=32 оправдан**: и по статистике, и по допуску ±1.0 дБ эффект значим. Но **d=8 — тоже приемлем**: выигрыш относительно эталона +7.45 дБ (тоже много).

### 6.4. Намеренная ошибка и диагностика

**Симптом:** PSNR 24.8 дБ для d=8 кажется «хорошим». Но **без эталона** непонятно, насколько.

**Диагностика:**
- Эталон «средняя картинка» = **17.31 дБ**. Модель лучше на **+7.45 дБ**.
- Диагностика по d: PSNR **растёт монотонно**, **насыщения нет** даже при d=32. Набор `two_discs` требует **больше ёмкости**, чем `disc`.
- **Сцена 4** на comparison.png при d=8 показывает **слипание** дисков — прямое визуальное подтверждение потери информации.

**Исправление:** для наборов с **m независимыми факторами** нужен **d ≥ m**. Оценка «хорошо/плохо» **невозможна без эталона**.

### 6.5. Угрозы валидности

- **Один набор, один фактор.** Проверены только `two_discs` и `latent_8_to_32`.
- **Одна архитектура** (свёрточная). Результат не переносится на полносвязную.
- **Синтетические сцены** с гладким фоном. Реальные фото — сложнее.
- **PSNR не различает** сдвиг объекта и размытие.
- **Время GPU-зависимо**, не воспроизводится между сессиями.
- **Допуск ±1.0 дБ** выбран условно.
- **5 seed** — малая серия.

**Цель достигнута.** Построен свёрточный автокодировщик, измерено качество реконструкции на отложенной выборке, проверено влияние размера латентного вектора по серии из 5 seed.

**Основные результаты:**

1. **PSNR:** +1.536 дБ (24.76 → 26.30). **За допуском ±1.0** → **улучшение**. Рост d с 8 до 32 **окупается** для набора `two_discs`. Значимо по 2s (4.98) и по допуску.
2. **Разрыв train − test:** +0.010 дБ — **в допуске**. Переобучения нет: прирост PSNR не за счёт запоминания.
3. **Параметры:** +49 тыс. (101 → 150 тыс., +49 %) — рост ёмкости. Изменились только последний слой кодировщика и первый слой декодировщика.
4. **Время:** −3.5 % — в допуске. GPU-зависимо.
5. **Эталон «средняя картинка»:** 17.31 дБ. Модель лучше на **+7.45 дБ** (A) и **+8.99 дБ** (B) — модель действительно восстанавливает сцену.
6. **Диагностика по d:** PSNR растёт монотонно, **насыщения нет даже при d=32**. Набор `two_discs` (4 фактора) требует больше ёмкости, чем `disc` (3 фактора).

**Ключевое объяснение.** Набор `two_discs` имеет **4 независимых фактора**. При d=8 сеть вынуждена сильно сжимать → теряется точность. При d=32 — запас ёмкости → PSNR растёт. **Оценка глазами:** в режиме A диски слипаются (видно на сцене 4); в режиме B — оба диска различимы.

**Воспроизводимость.** Результат **совпадает с эталоном преподавателя** в пределах 0.02 дБ по PSNR и gap, **точно** по параметрам. Время различается (~15 %) — GPU-зависимо.

**Практический вывод.** Для наборов с m факторами рекомендуется **d ≥ m**. Оценка PSNR **без эталона «средняя картинка»** бессмысленна. Чувствительность к допуску: при ±1.5 дБ эффект стал бы «нейтральным» — вывод об **улучшении** устойчив, но не абсолютен.

**Ограничения.** Один набор, одна архитектура, синтетика, 5 seed. Результат не переносится на реальные изображения без проверки.
